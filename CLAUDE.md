# EcologicalCellularAutomata.jl

A model zoo of published ecological cellular automata, from plant diseases and agricultural and forest pests to coastal dunes, each runnable on any compatible `CellularAutomataCore.jl` backend.

## Place in the ecosystem

Dependency order (arrows = depends on): CategoricalCellularAutomata → CellularAutomataCore and
EcologicalCellularAutomata → CellularAutomataCore. The zoo does not depend on the categorical package.
This package depends on: `CellularAutomataCore.jl`, through `[sources]` paths to sibling directories, and FFTW, Random and TOML.

The shared bibliography lives in the development workspace that holds the three packages side by side;
the `references.bib` files here are synced copies.

## Invariants that must not be broken

- No Catlab, GATlab or ACSets: within the ecosystem the zoo depends on `CellularAutomataCore.jl` only; its
  other dependencies are FFTW (which loads the core's FFT kernel fields), Random and TOML.
- Scope is published ecological cellular automata: plant diseases and agricultural and forest pests, and
  bio-geomorphology (landforms shaped by vegetation, such as coastal dunes). Every model has one of the
  registry's categories.
- Every model has a `models/<id>/metadata.toml` with a `fidelity` of `reproduction`, `adaptation` or
  `inspired`, and its vignette states the deviations from the source. Citation, DOI and model details are
  checked against the primary paper before they are recorded.
- Every model is a `CellularAutomataCore` `CAModel` built by `build_<id>` and registered with `_register!` at
  the end of `src/models/<id>.jl`; `problem_<id>` gives the source's setup. Dynamics that a local rule cannot
  express (individuals acting one at a time, decisions on the whole lattice) are `DiscreteCallback`s stored
  with the problem; they draw from a `Xoshiro` seeded from the problem's seed and the time, never from a global
  RNG, so runs agree across backends.
- Model tests check one-step transition frequencies against probabilities written out from the source's
  equations, never against the package's own code paths.

## Layout

- `src/EcologicalCellularAutomata.jl`: module docstring, exports, includes.
- `src/errors.jl`: the root `EcologicalCellularAutomataError` and every exception under it.
- `src/registry.jl`: `ModelInfo`, the metadata reader and checks, `list_models`, `model_info`, `build`, `problem`.
- `src/models/<id>.jl`: one file per model; `models/<id>/metadata.toml`: its metadata.
- `test/test_registry.jl`, `test/test_models.jl`: the registry and the models.
- `test/runtests.jl`, `test/test_errors.jl`, `test/test_docstrings.jl`: the suite, seeded RNGs only.

## Commands

```sh
julia --project -e 'using Pkg; Pkg.instantiate(); Pkg.test()'   # the test suite
julia --project=docs docs/make.jl --no-deploy                     # build docs locally
julia scripts/render_vignettes.jl                                 # render out-of-date vignettes to html/gfm/pdf, running each one's code once (cached; PDF needs lualatex + ../fonts/JuliaMono)
julia scripts/sync_vignettes.jl [--check]                         # copy vignettes into docs/src/tutorials
```

## Files not to edit by hand

- `docs/src/tutorials/` is generated by `scripts/sync_vignettes.jl`.
- `vignettes/*/*.md`, `*.html`, `*.pdf` and `*_files/` are quarto output; edit the `.qmd`.
- `docs/src/references.bib` and `vignettes/references.bib` are copied from the workspace
  `docs/references.bib` by `scripts/sync_references.jl`; edit the workspace copy.

## Style

JuliaFormatter `yas`; docstrings on every exported name, which `test/test_docstrings.jl` enforces; the docs
build is strict (no `warnonly`), so a docstring left out of the manual or a broken `@ref` fails it; typed
exceptions with the offending names in the message: they live in `src/errors.jl` and
subtype `EcologicalCellularAutomataError`, invalid arguments and keywords raise `ArgumentError`, typed errors from a lower package pass
through unchanged and documented, and another package's type is named as a code span, never with `@ref`;
seeded RNGs only in tests; every optimised code path is tested against a slower reference; no emojis in code
or docs.
